# Philippine Zonal Value Map

A free, public map of BIR residential zonal values (₱ per square meter of land) for Metro Manila and its outskirts: Cavite, Laguna, Rizal and Bulacan. Values are shown per barangay where the data allows. Every area carries a flag saying how good its number is.

> **Zonal values are BIR tax floors, not market prices.** Read the map as a ranking. Check with the BIR Revenue District Office (RDO) before any transaction.

## Data sources

| What | Source | Where in repo |
|---|---|---|
| Zonal value schedules (primary) | BIR Department Orders, published per RDO at [bir.gov.ph](https://www.bir.gov.ph) | `raw/bir/RDO-<code>/*.xls(x)` |
| Zonal values (fallback, until raw files exist) | BIR schedules as indexed by [REN.PH](https://ren.ph/tools/zonal-value) | `data/ncr_barangays.csv`, `data/pasay_barangays.txt`, `data/city_medians.csv` |
| Barangay and city boundaries | PSA / NAMRIA, PSGC Dec 2023 release, via [faeldon/philippines-json-maps](https://github.com/faeldon/philippines-json-maps) | fetched into `cache/` (not committed) |

### Quality flags

Every map feature has one of these flags:

- `barangay_data`: computed from that barangay's own schedule rows
- `city_median`: no barangay detail, so it shows the city's median residential value (hatched on the map)
- `estimated`: no data, so it shows the median of the neighbouring barangays it shares a border with (hatched and muted on the map)
- `no_data`: nothing usable (grey)

### Values per barangay

- **Interior lot**: the lowest residential value in the barangay
- **Prime**: the highest residential value
- **Typical**: the median of street-level residential values. Where only a min and max exist, the geometric mean of the two is used instead.
- **Adjusted**: the value projected to the current year using the RDO's median growth between schedule revisions. Both the raw and adjusted values are always shown.


## Rebuilding

Needs Node 20+ and Python 3.11+.

```bash
make venv    # one-time: creates .venv and installs pipeline/requirements.txt
make data    # fetches boundaries (cached), parses raw/ + data/, writes public/data/
make test    # pytest on the parser and name normalizer
npm install
npm run dev  # local site at http://localhost:5173
```

`make data` writes review files to `pipeline/review/`. If a barangay lands in `unmatched.csv`, add a row to `pipeline/aliases.csv` and run `make data` again.

## Adding new BIR schedules

1. Download the RDO's zonal value workbook from the BIR site and drop it, as is, into `raw/bir/_inbox/` (subfolders and odd file names are fine).
2. Run `make data`. It reads each workbook's NOTICE sheet and Department Order headers, files it under `raw/bir/RDO-<code>/` (for example `RDO-027`, `RDO-53A`), skips exact duplicates, and rewrites `raw/bir/inventory.csv`: one row per Department Order with its effectivity date and the cities it covers.
3. Check what needs a human:
   - `raw/bir/inventory_log.txt`: anything that needed judgment while reading the workbooks
   - `pipeline/review/unmatched.csv`: BIR barangay names that matched no PSGC barangay. Add a row to `pipeline/aliases.csv` and run `make data` again.
   - `pipeline/review/plausibility.csv`: values worth a second look
   - `pipeline/review/parse_errors.csv.gz`: every sheet row the parser could not use, with the reason (local only)
4. Commit and push; Vercel deploys `main`.

### How values are computed

- Only residential land rows (class `RR`) count. Condominium rows (`RC`) are priced per sqm of floor area, not land, so they are left out.
- Each barangay uses the newest Department Order that covers it. Typical is the median of its street values, each street counted once; interior lot is the minimum, prime the maximum.
- Where no BIR schedule matched a barangay, it is estimated as the median of the neighbouring barangays that have their own values (flagged `estimated`, hatched on the map). Only real values are used, never other estimates. With no such neighbour, it shows the city median (flagged `city_median`).
- **Adjusted to today.** For each RDO, every street that appears in two consecutive revisions of the same barangay gives one annual growth rate; the RDO's rate is their median, taken from the transition into its current schedules. An RDO with fewer than 20 such pairs uses earlier transitions, then its province's median. Each value is then grown from the date it was actually set (a schedule that only repeats an older one's values does not count as a new date). Department Order averages are never compared. Rates per RDO are in `pipeline/review/growth_by_rdo.csv`; the summary is in [docs/staleness-report.md](docs/staleness-report.md).
